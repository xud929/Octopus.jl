## Formula and protocol checks

1. Independently multiplied `N_out * R(mu) * inv(N_in)`. Its four entries are
   `sqrt(beta2/beta1)*(c+alpha1*s)`, `sqrt(beta1*beta2)*s`,
   `(-(1+alpha1*alpha2)*s+(alpha1-alpha2)*c)/sqrt(beta1*beta2)`, and
   `sqrt(beta1/beta2)*(c-alpha2*s)`, exactly the ordinary optics sibling's
   block. This verifies the separate entrance/exit normalizers rather than
   relying on a periodic-only identity.
2. Followed the row-major matrix products and transforms: `A = Mzeta * Meta *
   C * N`, with inverse entrance applied before the particle rotation and
   exit normalization applied afterward. Signs/order agree with the existing
   canonical dispersion implementation and theory (D2)–(D8).
3. The rotation of `q + im*p` is `exp(-im*2pi*nu)*(q + im*p)`, agreeing with
   the sign in the finite-ensemble response oracle. Signed stored tunes are
   retained; only cached trigonometry reduces modulo one.
4. Source groups are normalized by plane mask, reject overlaps, and preserve
   the user-declared ordering within a joint group. NamedTuple results are
   selected by name. Every result is checked finite/real/non-Bool before and
   after precision conversion. Arrays use global indexing after owned local
   labels are allocated; they never alias live label arrays.
5. Counter keys retain seed/method/stream/global particle identity and explicit
   preparation epoch. Component packing reserves the high bit and separate
   nonoverlapping plane-mask/draw fields. The maximum draw check fires before
   namespace wrap. Rejection sampling cannot consume another particle's or
   named group's counter stream.
6. Histogram shape, strict edges, bin-mass interpretation, cumulative-mass
   representability, zero-mass bin exclusion, and multidimensional Julia
   column-major bin indexing were traced. The sampler selects by mass and
   samples each coordinate inside its selected interval; it does not multiply
   mass by interval width.
7. The bound runtime drops host source objects, carries backend array views,
   and checks global-to-local indexing before table access. Its scalar and
   ambiguous Matrix entries refuse. Kernel error strings are static. Matrix
   and rotation arithmetic spell the FMA sequence on both CPU and CUDA.
8. Friendly construction claims stochastic streams once; runtime construction
   never claims. Raw stochastic specs require a nonzero resolved ID. Ordinary
   `Linear6D` remains the default and retains its wider Number support.

These are mathematical/source checks, not measured error bounds. Numerical,
CUDA and MPI results must be read from the executing units' receipts.

## Leads, corrections and dispositions

### LEAD U2-1 [Moderate, confidence high] src/contracts/Contracts.jl:2639 (pre-integration location)

Claim: The symplecticity declaration-to-case census initially covered only the
kind's default runtime and could not see the newly declared particle variant.

Mechanism: `RT = meta.runtime_type` examines `Linear6D`, so an existing ordinary
case satisfies the obligation even when `ParticleLinear6D` has no case. The
standalone validation sibling also directly scalar-called each case, which
would refuse a bound particle map.

Repro: Temporarily append `Base.RefValue` to
`element_meta(:linear6d).runtime_variants[Symplectic6DMap]`, run
`validate(SymplecticityContract())`, then restore the tuple. The corrected
contract must fail with `runtime_variants_declaring_without_case == 1` and
name `linear6d`; the old default-only census could not observe this mutation.
The committed "Contract coverage guards" testset performs this control.

Disposition: Parent integrator identified the seam during its independent
source census and requested the implementation correction. I added a real
one-particle, callback-prepared `ParticleLinear6D` case, with labels frozen
through all finite differences. The case records callback calls and requires
exactly one. The census now derives every `runtime_variants` member. The
shared `_symplecticity_case_track` is used by both contract and standalone
validation script. The parent's focused run passed the real contract, recorded
source_calls=1 and residual 1.997467913017353e-12, and confirmed the injected
missing-variant control fails by name. The complete existing coverage-guards
testset remains a full-suite obligation.

### LEAD U2-2 [Moderate, confidence high] src/knowledge/Knowledge.jl:1329 (pre-correction location)

Claim: A generic non-default runtime representative could be compiled under its
row's method but executed under the representative's original method.

Mechanism: `_check_runtime_variants!` passed `method()` to compilation and then
called `_element_metadata_probe(spec, coordinates)` without copying that
method into the probe spec. The current particle variant uses one method, so
its numerical validation was unaffected; the newly public generic variant
mechanism promised a stronger guarantee than this call provided.

Repro: Build `LumpedRadSpec(damping_turns=(4.,5.,6.), is_excitation=false)`;
prepare its row for `Diffusion6DMap` and execute `_element_metadata_probe` at
nonzero coordinates. The selected diffusion method is exactly inert, while
the original radiation method damps. The committed metadata test checks both
consumer outputs and that the original spec still uses `Radiation6DMap`.

Disposition: Parent authorized the scoped correction. The helper now copies
parameters, sets the row method and probes the new raw spec, leaving the
metadata representative untouched. The discriminating consumer fixture was
added; the parent's focused metadata testset subsequently passed 23/23,
including this consumer fixture and the three malformed variant controls.

### LEAD U2-3 [Moderate, confidence high] test/runtests.jl (One rng_id policy testset)

Claim: The existing RNG claim-site census still expected the four old consumer
classes after the new `:particle_tunes` consumer was introduced.

Mechanism: The source scan correctly discovers all named claim sites, but its
explicit expected set would reject the newly introduced fifth class. The old
policy test also had no fixture exercising that class's construction behavior.

Repro: Run the existing named "One rng_id policy" testset with
`src/elements/particle_tunes.jl` loaded. The old expected set cannot equal the
source-derived set containing `:particle_tunes`.

Disposition: Parent authorized updating the testset. It now exercises
particle-tune deterministic no-claim, stochastic zero-ID allocation, distinct
UInt64 IDs, no fresh claim during recompilation, explicit same-class reuse,
cross-class sharing warnings, and raw-zero refusal before admitting the new
class to its expected set. The actual source scan remains in place. The
parent's focused run subsequently passed the complete RNG policy testset,
43/43.

### LEAD U2-4 [Moderate, confidence high] src/registry/Registry.jl (snapshot publication)

Claim: The generated snapshot had no general public-helper/query index, so the
new exported source constructors and lifecycle/query functions would be absent.
`ParticleLinear6D` was correctly discoverable through the runtime variants;
`TuneFunction`, `TuneDistribution`, `TuneHistogram`, `runtime_variants`,
`runtime_examples`, `clear_particle_tunes!` and `particle_tune_tables` were not.

Mechanism: The generator derived architectural types and element runtimes,
then supplied a few handwritten macro/workflow indexes. These source objects
are neither Core Objects nor compiled runtimes. Existing unrelated helpers
were similarly incomplete: noise types appeared incidentally in the example
catalogue and the coordinate-reset clear function was absent.

Repro: Generate the snapshot and compare its exact backticked name tokens
against Julia's live `names(Octopus)`, excluding the module's own name. The
pre-fix snapshot cannot contain the seven new names above.

Disposition: Parent approved a compact alphabetical Exported API index derived
from module exports. It adds no Knowledge category or registry field, and does
not classify source wrappers as kernel runtimes. The new testset compares all
exported names to exact single-line backticked tokens and deletes every
`TuneFunction` token to prove omission detection. The prepared Registry patch
was applied only after the parent's earlier focused run completed. Publication
execution subsequently passed 17/17, including the omission control, and the
parent regenerated the snapshot. I confirmed the resulting runtime mapping
and the seven public names in the generated file.

The validation agent independently found a UInt32 adapter failure on its first
focused run; the original call to Julia's internal `Random.rand_generic`
was unsupported for that argument form. Core replaced it with checked-width
integer bit conversions and explicit 128-bit assembly. I inspected the
replacement but did not discover or execute that defect. Its measured failure
and rerun belong to the validation unit.

No additional core map/source/RNG defect was established by this read.

## Independent final comparison to the user's agreement

I reread the complete final design note and compared it with the supplied
conversation's agreed interface. No outstanding deviation was identified:

| User agreement | Final design and integration |
|---|---|
| Reuse `Linear6DSpec`, compile a different runtime | Same `:linear6d` kind and constructor; declared `ParticleLinear6D` variant |
| Shared Twiss, crab and momentum dispersion normalizers | Shared entrance inverse and exit transform, retaining coupling and unequal optics support |
| Assign fixed per-particle nux/nuy/nuz on first passage | Task-owned labels initialized at the actual element boundary; cached rotations use each stable particle slot |
| Functions use physical `(x,px,y,py,z,pz)` | Six-argument entrance-coordinate protocol, before normalization, once per successful assignment |
| Function, distribution and direct-array inputs | Explicit source protocols and constructors; joint named distributions and correlated direct samples supported |
| Any partial override, including nuy or nuz alone | All seven nonempty subsets; omitted tunes frozen from dmu/(2pi) |
| General element does not know the beam count | Array length checked against resolved global count at task binding; spec owns no mutable table |
| Tables survive continuation and coordinate reset | Binding state persists outside runtime/plan caches; resets and explicit tune clear have independent lifecycles |
| Keep runtime data on CPU/CUDA execution device | Owned local arrays, cached sine/cosine arrays, one-time host source evaluation/upload and indexed device tracking |
| Validate mapping, physical response and supported policies | Dense independent oracle, frozen-label symplecticity, phase mixing and kick sums, lifecycle/refusal tests, CPU/CUDA and actual MPI checks assigned to measured units |

Metropolis-Hastings remains an external distribution/sample producer; the
user accepted function/distribution/direct arrays rather than requesting a
built-in chain algorithm. The built-in histogram sampler directly samples bin
masses, with joint correlations supported. Explicit first-version boundaries
remain documented: Float32/Float64 active variants, optics construction,
TrackingTask with direct/flattened placements, no arbitrary action hooks,
contextless Matrix/Twiss refusal, no StrongStrongTask or nested/wrapped active
placement support. These were visible in the reviewed note before
implementation; none silently substitutes a different physical map. Wider
support and a full crab-noise/beam-beam scientific comparison remain separate
work, not demonstrated by this feature validation.
