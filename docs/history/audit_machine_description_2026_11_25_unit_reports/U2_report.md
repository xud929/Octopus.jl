### LEAD C-1 [Major, confidence high] src/tasks/BeamObservers.jl:57
Claim: `AtTurns` compares by identity, so two independently built lines whose solvers schedule luminosity on equal `AtTurns` are refused as differently configured.
Mechanism: `struct AtTurns` holds a `Set{Int}` and defines no `==`; the fallback is `===`, which compares a mutable field by pointer. `solver_configuration` copies the field into its NamedTuple, NamedTuple `==` compares the field by `==`, and `_collision_solver` (interface.jl:3989-3991) throws on the inequality.
Repro: `julia --project=WT --startup-file=no /tmp/claude-dxu/md5/C/probe.jl` -> `L1 AtTurns(Set([1,2])) == AtTurns(Set([1,2])): false`, `L1 solver_configuration(s1) == solver_configuration(s2): false`, `L1 _collision_solver(task, ip1, ip2): ArgumentError: collision ip specifies different Poisson solver configurations in line1 and line2` (Gaussian and PIC pairs alike; the `EveryNSteps` control pair ACCEPTED).
Root response: confirmed and fixed in the batch -- `Base.:(==)`, `isequal` and `hash` on `AtTurns` by its set (the `LongitudinalSlicing` precedent), BeamObservers.jl after the convenience constructor; regression test "Machine description audit: AtTurns compares by its set, so independently built solvers scheduling the same turns pair", shown red on the unfixed tree (red_L1_L2.log). Blast radius measured by grep (Lesson 2): no `src/` or test site compares schedules by identity on purpose; `unique(solvers)` (interface.jl:2583) hashes solver structs, unchanged; the lattice walker already compared `AbstractSet` by content. `EveryNSteps` (Int fields) and `AlwaysSchedule` were value-equal; `PredicateSchedule` compares its function by `===`, which is right.
