## Leads

### LEAD U2-1 [low, confidence high] src/elements/strong_beam.jl:719
Claim: `_cross_backend_rounding` is the one reader in H1's list where the two kinds take different branches: a round beam spelled `GaussianStrongBeamSpec(...; ns = 1)` is held to a 64-ulp cross-backend bound while the identical kernel spelled as the thin kind is held to 8.
Mechanism: `_cross_backend_rounding(op::ThinStrongBeam)` (strong_beam.jl:351-356) declares `ulp_bound = round_beam ? 8 : 2048`; `_cross_backend_rounding(op::GaussianStrongBeam)` (:719-724) declares `round_beam ? 64 : 2048` from a 3-slice measurement (11 ulps) and never consults `op.ns`. With `ns = 1` and no sigz, `_gaussian_slices` returns `(zero(T),), (one(T),)` (:1875-1881), so the CUDA kernel runs `kbb * 1`, `xo + 0`, `zo + 0` -- bit for bit the thin launch -- yet the acceptance is 8x looser. Conservative, not wrong; but the stage-2 migration moves acceptance with the spelling, and nothing states that. The in-tree asserters kept the thin kind (runtests.jl:18510-18512 `round_beam()` via `_thin_strong_beam_spec`; validation/tracking_backend_consistency.jl:142,170), so no check in the tree loosened; a user's script migrating a round thin beam to `ns = 1` would.
Repro: `julia --project=. -e 'using Octopus; t = Octopus._cross_backend_rounding(compile_runtime(Octopus._thin_strong_beam_spec(; kbb=1e-8, beta=(1.0,1.0), sigma=(1e-4,1e-4)))); g = Octopus._cross_backend_rounding(compile_runtime(GaussianStrongBeamSpec(kbb=1e-8, beta=(1.0,1.0), sigma=(1e-4,1e-4), ns=1))); println((t.ulp_bound, g.ulp_bound))'` prints `(8, 64)`; the two compiled elements track the same particle to the same bits on both backends (the stage-2 record's `ns = 1` identity pin).

- The constructor STORES `thin=thin_spec, ns, sigz, slice_method, slice_width, slice_center, slice_weight, slice_*offset, mean, covariance, hvoffset, tracking_method, kwargs...` (strong_beam.jl:665-684) and never `kbb`/`beta`/`sigma`/`klum`/`center`/`angle`: the self-contained keywords are folded into `thin` (:621-660). `params(example)` therefore carries `thin => ElementSpec{:thin_strong_beam}` plus `nothing` for the unset keys (`_spec_params` keeps every kwarg, linear_maps.jl:8-10), and passing them back (`mean=nothing`, `hvoffset=nothing`, `slice_*=nothing`) is "not given" to the constructor (:565-569, :594).
