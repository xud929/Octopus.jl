## Leads and dispositions

- **L4a (U8) The class form across the registry.** The first smoke run (the
  methods generated by a loop in `templates.jl`) found 30 kinds deriving and
  the aperture without a method (`MethodError: no method matching
  ApertureSpec(::ElementSpec{:aperture}; name)`): `src/elements/aperture.jl`
  is included from `src/Octopus.jl:114`, after `Elements.jl` (line 93).
  **Confirmed, fixed in the batch:** the registration installs the method
  (`_install_class_form!`); the second run derives 31 kinds, the aperture
  included (`ApertureSpec(ap; name = "COLL_H2", x_limit = 1.0e-2)` keeps
  `shape`); the suite's registry-derived tripwire holds it.
- **L4b (U8) The RBEND template.** There is no `:rbend` kind
  (`RBendSpec(; kwargs...) = SBendSpec(; _rbend_params(kwargs)...)`,
  `src/elements/lattice_magnets.jl:1667`), so the first `_derive_spec` had a
  dead `kind === :rbend` arm and `RBendSpec(template; ...)` had no method
  (the first smoke run's `MethodError`). **Confirmed, decided and fixed in
  the batch** (the record's section 2): the alias has its own method reading
  the template as an RBEND; `RBendSpec(rb; angle = 0.2)` on `rb =
  RBendSpec(; L = 1, angle = 0.1)` gives faces of 0.1, `chord = 2.0`
  doubles the arc, a no-change derivation is equal to roundoff, a template
  with `h != b0` is refused by name.
- **L4c (U8) Typed templates.** A `Float32` template in an `@elements Float32`
  block derives `Float32` (`kn = (0.0f0, 2.0f0)`); a `Float64` request on a
  `Float32` template is refused by name; the thin crab cavity's example
  derives typed `Float32` through its `numeric_type` keyword; the strong
  beam's example derives; `_with_numeric_type` on a folded quadrupole keeps
  `kn`. **Clean.**
- **L4d (U8) The fold hook under the knob rebuild.** `SBendSpec(; L = 1,
  angle = @knob_expr(ap4.ang))` stores `h`/`b0` as the expression (no
  `angle`), compiles `h = 0.1` and `0.2` after a retune (the rebuild passes a
  folded dictionary, which the hook leaves alone), and derives at a new
  angle (`0.3`); the typed flexible form `ElementSpec{:sbend}(; numeric_type
  = Float32, L, angle)` folds to `h = 0.1`. **Clean.**
- **L4e (U8) The flexible form's blast radius.** The grep of
  `ElementSpec{:<kind>}(` with a named strength over `test/`, `examples/`,
  `validation/`, `profiling/` finds one site, the suite's thin-quadrupole
  both-spellings refusal (now raised at construction, still an
  `ArgumentError`; the block passes extracted); `src/` constructs no
  flexible form with a named strength outside `@element_spec` examples,
  which run before the hook is installed and through friendly constructors.
  **Clean.**
- **L4f (U8) The docstring sweep.** The RBEND alias's method docstring
  attached to `Core.Type` and failed the suite's detached-docstring sweep
  extracted (`Core.Type <- Union{Tuple{ElementSpec{K}}, Tuple{K}} where K`).
  **Confirmed, fixed in the batch:** the text is a comment, the rule lives in
  `_derive_spec`'s docstring; the sweep re-run extracted passes.
- **L6 (U7) Three files.** `read_machine(pa, pb, pc; name = "ABC")` assembles
  the three lattices in argument order with their own references. A root
  two files declare that the assembled machine does not declare shared is
  refused by `Machine`'s tripwire through the reader (the U7 testset pins
  it, after the auditor's own first expectation -- an empty shared root --
  was wrong and corrected). **Clean.**
- **L14 (U7) The one-file reader.** `read_machine(path)`'s shape and receipt
  are unchanged (the codec blocks pass extracted; `read_lattice` is a
  wrapper over it). **Clean.**
